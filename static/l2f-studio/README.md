# L2F Studio

L2F Studio lives at `static/l2f-studio` inside the RLtools repository. Its build scripts use the headers in that same checkout and can be invoked from any working directory.

From the RLtools repository root, download the pinned dependencies and start a static server:

```bash
./static/l2f-studio/download_dependencies.sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Open <http://localhost:8000/static/l2f-studio/>. You can also serve `static/l2f-studio` directly and open the server's root URL.

The downloader creates depth-1 detached checkouts in `static/l2f-studio/external/`: `blob` contains the prebuilt JavaScript/WASM modules, policy checkpoint, and dynamics registry; `conta` contains meshes and scenes; `json` supplies nlohmann/json headers for rebuilding. The downloaded assets are sufficient to run the studio.

To rebuild against the current RLtools sources, install Docker and run:

```bash
./static/l2f-studio/build_emscripten.sh
./static/l2f-studio/build_dyn_inference.sh
```

Both scripts use `emscripten/emsdk:4.0.17` and write their output to `static/l2f-studio/external/blob/`. To rebuild the JavaScript dependency bundles, install Node.js/npm and run:

```bash
./static/l2f-studio/bundle.sh
```

This installs the versions in `package-lock.json` and writes the bundles to `external/blob/lib/`. The studio uses the WASM inference backend and does not require a separate `rltools.js` package.

Mixed visual checkpoints with image input `[T,B,50,160,8]` and sensor input `[T,B,65]` require both WASM modules to be rebuilt. Load the checkpoint with the existing file or URL loader. Studio selects `crazyflie_openmv`, supplies the paired current/target images and Mahony/IMU observations, and uses the CTBR action interface. The target image is captured at the origin with identity orientation; trajectory controls are hidden while this policy is active. Switching to Controller or Gamepad restores direct motor control and resets the simulator state.

The compatibility checks use Node.js and the repository's `.venv` with `h5py` installed. After rebuilding, run from the repository root:

```bash
timeout 20s node static/l2f-studio/wasm/test_visual_policy.mjs /path/to/checkpoint.h5
```

This compares image packing and repeated single-example inference against the checkpoint's saved examples, checks CTBR hover and sensor/reset behavior, and checks the legacy observation layout.

The dynamics registry is generated by `src/rl/environments/l2f/export_dynamics.cpp`. With RLtools configured and JSON support enabled:

```bash
cmake --build build --target rl_environments_l2f_export_dynamics --parallel 5
./build/src/rl/environments/l2f/rl_environments_l2f_export_dynamics
```

The exporter writes to `static/l2f-studio/external/blob/registry` in the source checkout used to configure the build.

To debug either WASM module:

```bash
DEBUG=1 ./static/l2f-studio/build_emscripten.sh
DEBUG=1 ./static/l2f-studio/build_dyn_inference.sh
```

In the Chrome C/C++ DevTools extension, substitute these paths, replacing `/path/to/rl-tools` with your checkout's absolute path:

```text
/rl_tools => /path/to/rl-tools
/mnt => /path/to/rl-tools/static/l2f-studio/wasm
/tmp/src => /path/to/rl-tools/static/l2f-studio/wasm
```
